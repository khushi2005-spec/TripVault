# TripVault ✈️

**Save your journeys. Keep your memories.**

TripVault is a full-stack travel memory management application built with React, Node.js, Express, and MongoDB. It allows users to create and manage trips, upload travel photos, and maintain public travel profiles.

## 🌐 Live Demo

- **Live Website:** https://trip-vault-seven.vercel.app/
- **Backend API:** https://tripvault-backend-xd5x.onrender.com
- **GitHub Repository:** https://github.com/khushi2005-spec/TripVault

## 📌 Overview

TripVault provides a responsive interface for organizing travel experiences. Users can register, log in, manage personal trips, upload photos, and configure public profiles.

The application uses JWT-based authentication with HttpOnly cookies, backend authorization, and CSRF protection for applicable state-changing requests.

## 🔒 Authentication and CSRF Protection

TripVault uses JWT-based authentication with an HttpOnly cookie.

### Authentication Flow

```text
User Registration
       |
       v
Password Hashed with bcryptjs
       |
       v
User Stored in MongoDB
       |
       v
User Login
       |
       v
JWT Generated by Backend
       |
       v
JWT Set in HttpOnly Cookie
       |
       v
Browser Sends Authentication Cookie
       |
       v
Backend Verifies JWT
       |
       v
Protected Resource Access
```

The authentication cookie is not accessible to client-side JavaScript. The browser manages the cookie when making requests according to the application's cookie and credential configuration.

### CSRF Protection

The backend provides a CSRF token endpoint. The frontend obtains the token and sends it in the `X-CSRF-Token` header for applicable state-changing authenticated requests.

The backend validates the token according to its CSRF middleware configuration.

## 🌐 API Endpoints

The following table documents the principal API routes. All endpoints are relative to the backend base URL.

### Authentication APIs

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/auth/csrf` | Obtain a CSRF token |
| POST | `/api/auth/register` | Register a user |
| POST | `/api/auth/login` | Authenticate a user |
| POST | `/api/auth/logout` | Log out and clear authentication cookies |
| GET | `/api/auth/me` | Retrieve the authenticated user |

### Trip APIs

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/trips` | Create a trip |
| GET | `/api/trips` | Retrieve the authenticated user's trips |
| GET | `/api/trips/:id` | Retrieve an individual trip |
| PUT | `/api/trips/:id` | Update a trip |
| DELETE | `/api/trips/:id` | Delete a trip |
| POST | `/api/trips/:id/upload` | Upload a trip image |

### Profile APIs

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/users/:username/profile` | Retrieve a public profile |
| PUT | `/api/users/profile` | Update the authenticated user's profile |

Protected endpoints require valid authentication. State-changing requests must also satisfy the backend's CSRF validation rules where applicable.

## 🚀 Deployment

TripVault uses separate services for the frontend and backend.

| Component | Platform |
|---|---|
| Frontend | Vercel |
| Backend | Render |
| Database | MongoDB Atlas |
| Image Storage | Cloudinary |
| Source Control | GitHub |

### Frontend Configuration

Configure the following environment variable in the Vercel project settings:

```env
VITE_API_URL=https://tripvault-backend-xd5x.onrender.com
```

The frontend API service uses this base URL to communicate with the backend. Its request paths must match the API service implementation.

For local development, configure the API base URL for the local backend when necessary.

### Backend Configuration

Configure the required environment variables in the Render service settings:

```env
NODE_ENV=production
MONGO_URI=your_mongodb_connection_string
JWT_SECRET=your_strong_secret
CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
CLOUDINARY_API_KEY=your_cloudinary_api_key
CLOUDINARY_API_SECRET=your_cloudinary_api_secret
```

Configure any additional variables required by the actual backend configuration. Use the hosting platform's assigned port when applicable.

Never place production credentials in frontend code, the README, or public repositories.

## 📦 Installation and Setup

### Prerequisites

- Node.js and npm
- Git
- A configured MongoDB database
- Cloudinary credentials for image uploads

### 1. Clone the Repository

```bash
git clone https://github.com/khushi2005-spec/TripVault.git
cd TripVault
```

### 2. Configure the Backend

```bash
cd server
npm install
```

Create a `.env` file inside the `server` directory:

```env
NODE_ENV=development
PORT=5000
MONGO_URI=your_mongodb_connection_string
JWT_SECRET=your_development_secret
CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
CLOUDINARY_API_KEY=your_cloudinary_api_key
CLOUDINARY_API_SECRET=your_cloudinary_api_secret
```

Start the backend using the script configured in `server/package.json`. If the `dev` script is available, run:

```bash
npm run dev
```

### 3. Configure the Frontend

Open a second terminal from the project root:

```bash
cd client
npm install
```

If a local API URL needs to be configured, create `client/.env.local`:

```env
VITE_API_URL=http://localhost:5000
```

Start the frontend:

```bash
npm run dev
```

Vite displays the local frontend URL in the terminal, normally `http://localhost:5173`.

Ensure that the backend CORS configuration permits the local frontend origin and that cookie and CSRF settings are compatible with the development environment.

### 4. Run Backend Tests

From the `server` directory, use the test script defined in `server/package.json`. For example, if the script is named `test`:

```bash
npm test
```

Consult the package scripts for the exact available test commands.
